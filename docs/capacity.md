# एक साथ हज़ार requests, कई providers के साथ

NavBharatAI से एक साथ 1000 requests आएं, और Mitrify में 6-7 providers हों, तब यह व्यवस्था है।

## Mitrify क्या करता है
1. **बंटवारा:** हर request पर सबसे सस्ता model चुना जाता है, पर अगर उसका provider अभी भरा हुआ है (उसकी एक साथ की सीमा पूरी), तो request **इंतज़ार में नहीं बैठती**, वह अगले सस्ते model पर चली जाती है जिसके provider के पास जगह है। इसलिए सारे providers काम में आते हैं, पर महंगा provider तभी जब सस्ते भर जाएं।
2. **हर provider की अपनी सीमा:** `MITRIFY_<NAME>_MAX_CONCURRENCY` से तय होती है कि उस provider को एक समय में कितनी requests दी जाएं। Mitrify उसे कभी पार नहीं करता (tests में जांचा गया)। सब providers भरने पर requests कतार में लगती हैं, कतार सबसे छोटी वाले provider की।
3. **कतार भर जाए** (`MITRIFY_<NAME>_MAX_QUEUE`) तो साफ़ `429` और `Retry-After` मिलता है, लटकता नहीं। कतार में इंतज़ार की अधिकतम देर `MITRIFY_GATEWAY_QUEUE_TIMEOUT_MS` (डिफ़ॉल्ट 90 सेकंड)।
4. **मेमोरी की रक्षा:** एक साथ संभाले जा रहे संदेशों का कुल आकार `MITRIFY_GATEWAY_MAX_INFLIGHT_MB` (डिफ़ॉल्ट 512) से ज़्यादा हुआ तो नई requests को `503` और "5 सेकंड बाद आओ" मिलता है, सर्वर गिरता नहीं।
5. **free और सशुल्क:** free models की खाते की सीमा (प्रति मिनट 20) भरते ही बाक़ी requests सशुल्क पर जाती हैं। हर request की आख़िरी कोशिश सशुल्क model को मिलती है (`docs/openrouter.md`)।

## आपको कौन-सी settings लगानी हैं (Hostinger → Environment variables)
| नाम | क्या डालें |
|---|---|
| `MITRIFY_<NAME>_MAX_CONCURRENCY` | **उस provider की असली सीमा** (उनके docs/खाते में देखें)। डिफ़ॉल्ट 32। बहुत ऊंची रखने पर provider `429` देगा, जो हम सह लेते हैं (cooldown) पर बेकार कोशिशें बढ़ती हैं |
| `MITRIFY_<NAME>_MAX_QUEUE` | कतार की लंबाई (डिफ़ॉल्ट 1000) |
| `MITRIFY_GATEWAY_MAX_INFLIGHT` | एक साथ खुली कुल requests (डिफ़ॉल्ट 1500)। हज़ार के लिए ठीक है |
| `MITRIFY_GATEWAY_MAX_INFLIGHT_MB` | मेमोरी की कुल सीमा (डिफ़ॉल्ट 512)। **अपने Hostinger plan की मेमोरी से कम रखें** |
| `MITRIFY_GATEWAY_QUEUE_TIMEOUT_MS` | कतार में कितनी देर (डिफ़ॉल्ट 90000) |

और **NavBharatAI वाली key का `rpm`** बढ़ाएं: owner पेज पर "Your API keys" में नई key बनाते समय **"Requests per minute"** में `6000` लिखें। डिफ़ॉल्ट 600 है, यानी हज़ार एक साथ आने पर 400 requests `429` पाएंगी।

## सच्चा गणित (इसे ज़रूर पढ़ें)
हज़ार requests **एक साथ शुरू** हो सकती हैं, पर एक साथ **पूरी** नहीं हो सकतीं। गति = (सब providers की एक साथ की सीमाओं का जोड़) ÷ (एक जवाब में लगने वाला समय)।

मिसाल: 7 providers, हर एक पर 30 एक साथ = 210 जगहें। अगर एक जवाब में 20 सेकंड लगते हैं, तो 1000 requests करीब 100 सेकंड में निपटेंगी (210 जगहें × हर 20 सेकंड में बदलती हुई)। कतार में 90 सेकंड की सीमा इससे ज़्यादा इंतज़ार कराएगी, इसलिए ऐसे में `QUEUE_TIMEOUT_MS` बढ़ाएं, या NavBharatAI को `429` पर backoff से दोबारा भेजने दें।

छोटे जवाब (कुछ सेकंड) के साथ यह सब बहुत जल्दी निपटता है।

## NavBharatAI की तरफ़ से
- `429` या `503` मिले तो **थोड़ी देर रुककर** (backoff + `Retry-After`) दोबारा भेजें, और अगर जवाब शुरू हो चुका था तो उसे दोबारा न चलाएं।
- एक साथ भेजी जाने वाली requests की अपनी सीमा रखें (जैसे 200-300), ताकि सब एक ही पल में न आएं। यह हमारी कतार से ज़्यादा सहज है।

## असली साइट पर परखना
```
MITRIFY_API_KEY=<key> N=20 node scripts/load-test.mjs               # छोटा परीक्षण
MITRIFY_API_KEY=<key> N=1000 CONFIRM=1 node scripts/load-test.mjs   # हज़ार एक साथ
```
(key को चैट या GitHub में न डालें। script उसे कभी छापती नहीं।) यह गिनती, समय, status codes और जवाब देने वाले models के नाम छापती है। **हर request पर थोड़ा खर्च होता है** (पहले free, फिर सस्ते सशुल्क), इसलिए `MAX_TOKENS` छोटा रखा गया है। हज़ार का परीक्षण तभी करें जब कोई सशुल्क provider जुड़ा हो और खर्च की सीमा (`MITRIFY_GATEWAY_DAILY_BUDGET_USD`) ठीक हो।

## जो अभी जांचा नहीं गया
- **Hostinger का आपका plan** हज़ार खुले जुड़ाव और 512 MB तक की मेमोरी संभालेगा या नहीं (साझा hosting में प्रक्रियाओं और मेमोरी की सीमाएं होती हैं)।
- **Hostinger के आगे का CDN** लंबी या कई streaming को काटेगा या नहीं।
- असली providers की असली सीमाएं और असली जवाबों का समय। tests नकली providers पर हैं (हज़ार requests, 7 providers, हर provider की सीमा पर कभी पार नहीं हुई)।
